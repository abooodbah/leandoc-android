# Test fixtures

Every file here is generated by `make-fixtures.py` and committed. The script
is deterministic: running it again rewrites the same bytes. It needs Python 3
and python-docx 1.2 (used for the template parts and a few fixtures).

```sh
python3 tests/fixtures/make-fixtures.py
```

| Folder | Contents |
| --- | --- |
| `security/` | Crafted files from SPEC section 6: ZIP and XML attacks, external references, macros, embedded objects, and the two OLE compound files. |
| `features/` | Documents from SPEC section 7 for the core tests and the reader tests. |
| `kinds/` | Classification by content: ODT, RTF, a spreadsheet, templates, Strict OOXML, and plain text with a Word extension. |

## Expectations

`expected.json` maps each fixture path to what the core must report. The
reader tests read the same file.

```json
{
  "features/not-displayed.docx": {
    "kind": "docx",
    "ok": true,
    "errorCode": "",
    "features": {"chart": 1, "equation": 1, "shape": 1, "smartart": 1, "text-box": 1},
    "rightToLeft": false,
    "outline": [[1, "Content LeanDoc does not display", 0]],
    "text": ["Content LeanDoc does not display", "A text box:", "..."],
    "purpose": "One sentence on what the fixture is for."
  }
}
```

- `features` lists every feature with a count above zero, by feature code.
- `rightToLeft`, `outline` (level, text, paragraph index), and `text` (the
  sanitized document's body paragraphs as plain text) are present only where
  they are checked.
- `expected.inc` is the same data as C++ initialisers for
  `tests/core/CoreTests.cpp`. Do not edit either file by hand.

Text boxes, equations, and shapes count only in the forms the reader's
docx-preview 0.4.1 does not draw (see `FeatureIsNotDisplayed()` in
`src/core/DocCore.cpp`). `features/not-displayed.docx` uses those forms;
`features/drawn-content.docx` holds the forms it draws and expects no
features.
